### Known issue (cosmetic, non-blocking, deferred)

The Intel SST mic name renders as `IntelÂ®` instead of `Intel®` in the built
exe's dropdown on the laptop, even after `--clean` rebuild. The `_fix_name`
function is in the bundled bytecode AND works correctly when extracted and
invoked manually against the problem string. Source-mode returns clean names.
Couldn't pin down despite bytecode inspection, manual invocation, locale
checks, clean-cache rebuild. Dropdown is still usable (one mic name has `Â®`
visible). Cleanest v1.0.4 fix would be a response-middleware that runs the
latin-1 -> UTF-8 transform on serialised JSON regardless of what
`devices_list` returns; that fully bypasses whatever request-time thing is
swallowing the function-level fix. **Test on the PC first** -- if the mojibake
doesn't appear there, it might be a laptop-locale-specific quirk and the fix
is already adequate for shipping.

### Also for v1.0.4: shorten the Stop drain on slow machines

Sean's first real session on v1.0.3 (laptop, 7:47 of Afrikaans) finished
cleanly but Stop hung at "Finishing, 4 chunks left" for several minutes
before the file closed. Console showed
`[engine] CPU RTF ~1.42 (> 0.95); downgrading large-v3-turbo -> medium`
mid-session -- the dynamic tier downgrade fired correctly, but only AFTER
the queue had already built up. Drain-on-stop did its job (no transcript
loss) but the wait was rough.

Two cheap improvements (still under `IMPROVEMENTS.md` item 2):

1. Default to `medium` on `cpu-strong` (or whichever tier covers Sean's
   laptop) so the first session doesn't have to build a backlog before
   the downgrade catches up. The fact that the runtime downgrade chose
   `medium` is evidence that medium is the right starting point on this
   class of hardware.
2. Trigger the RTF check sooner (currently waits to accumulate enough
   samples for a stable RTF). Even one chunk's RTF would be informative
   when it's >> 1.

Neither is needed for the v1.0.3 ship; queue them for v1.0.4 alongside the
mojibake middleware fix.
